Intégration caisse

PAR PixelPoint et HubRise : laquelle des 2 intégrations choisir

PixelPoint se connecte à HubRise de 2 façons, qui ne sont pas équivalentes. Le Bridge reçoit seulement commandes et clients. La Windows API envoie aussi votre carte. Choisissez selon que PixelPoint ou HubRise doit détenir la carte.

PAR PixelPoint

PAR PixelPoint en bref

PAR PixelPoint est une caisse (EPOS) disponible dans le monde entier. PixelPoint Bridge est une application HubRise, développée par HubRise, qui passe par la Web API de PixelPoint. PixelPoint Windows API est une application de Slowey Systems. HubRise n'indique ni types d'établissements ni appareils précis pour PixelPoint.

Prendre les commandes

  • Commande en ligne

    Order&Pay

    Vos clients commandent et paient en 1 geste, sans application ni compte, et la commande arrive dans PixelPoint via HubRise. La carte qu'ils voient dépend de votre choix : la Windows API envoie le catalogue de PixelPoint, alors qu'avec le Bridge vous saisissez la carte dans HubRise et l'associez aux codes de PixelPoint.

    • Menu : PAR PixelPoint l'envoie à HubRise, donc les articles et les prix sont ceux de la caisse.
    • Commandes : envoyées à PAR PixelPoint via HubRise.

    Voir sur le commerce d'exemple

  • Écran cuisine et préparation

    OrderPicker

    OrderPicker prépare les commandes qui arrivent dans l'établissement via HubRise, comme écran cuisine (KDS) ou écran de préparation. Aucune des 2 intégrations ne renvoie à HubRise les commandes encaissées sur PixelPoint : seules les commandes téléphoniques, en ligne et des plateformes s'affichent. L'équipe avance article par article, puis marque la commande comme prête.

    • Ventes en caisse : elles restent dans PAR PixelPoint. Seules les commandes qui passent par HubRise sont incluses.

    Voir sur le commerce d'exemple

  • Commandes par téléphone

    OrderPad

    Les commandes téléphoniques arrivent dans PixelPoint avec l'une ou l'autre intégration. La fiche de l'appelant remonte depuis HubRise, et la commande est composée à partir de la carte HubRise, avec options, commentaires et livraison ou à emporter. Avec le Bridge, cette carte se configure dans Catalog Manager, avec correspondance des codes. Avec la Windows API, PixelPoint l'envoie.

    • Menu : PAR PixelPoint l'envoie à HubRise, donc les articles et les prix sont ceux de la caisse.
    • Commandes : envoyées à PAR PixelPoint via HubRise.

Faire revenir les clients

  • Campagnes e-mail et SMS

    Brevo Bridge

    Brevo Bridge copie les clients et les commandes de HubRise dans votre propre compte Brevo, triés par visites, panier moyen et dernière commande, en segments comme nouveaux, VIP et inactifs. Les ventes au comptoir de PixelPoint ne sont pas envoyées à HubRise : les segments viennent des commandes qui passent par HubRise.

    • Ventes en caisse : elles restent dans PAR PixelPoint. Seules les commandes qui passent par HubRise sont incluses.

    SMSMode Bridge

    SMSMode Bridge copie les mêmes clients et commandes dans votre propre compte smsmode, triés de la même façon, pour vos campagnes SMS et WhatsApp. Les commandes encaissées au comptoir PixelPoint n'arrivent dans HubRise avec aucune des 2 intégrations : elles ne font pas partie de l'audience.

    • Ventes en caisse : elles restent dans PAR PixelPoint. Seules les commandes qui passent par HubRise sont incluses.

Questions

Questions sur PAR PixelPoint et OnyLab

Quelle différence entre PixelPoint Bridge et la Windows API ?

Le Bridge, développé par HubRise, reçoit seulement commandes et clients de HubRise et ne peut pas envoyer la carte. La Windows API, développée par Slowey Systems, envoie aussi votre catalogue à HubRise.

De quoi ai-je besoin pour chaque intégration ?

Le Bridge exige PixelHQ et PixelPoint en version 12.3 ou ultérieure, ainsi que l'External Order Interface. La Windows API exige un serveur Windows en magasin avec Pixel SQLbase et Pixel License Manager, et se met en place via le support de Slowey Systems.

Pourquoi choisir le Bridge s'il ne peut pas envoyer ma carte ?

Si vous acceptez de saisir la carte dans HubRise et de l'associer par codes de référence, le Bridge livre quand même les commandes à PixelPoint. Si vous voulez que PixelPoint reste la source de la carte, choisissez la Windows API.

Faut-il un compte HubRise pour connecter PAR PixelPoint ?

Oui. Les applications OnyLab rejoignent PAR PixelPoint via le compte HubRise de votre commerce. HubRise a son propre abonnement, facturé par HubRise.
